# USOUSD.s (MT5) — Telegram-бот аналітики нафти WTI

Особистий Telegram-бот, який аналізує **CFD USOUSD.s** (нафта WTI) у **Bybit TradFi**
через **MetaTrader 5** (брокер Infra Capital Limited, сервер `Bybit-Live-6`), таймфрейм 5 хв.
Він бере з терміналу MT5 свічки, котирування, спред і тікову активність, додає свіжі новини
та календар подій (EIA, API, ОПЕК+), передає це моделі Claude і надсилає розбір з ймовірністю
лонгу та шорту.

- **За кнопкою** «📊 Аналіз зараз» — розбір приблизно за 20–40 секунд.
- **Автосповіщення** — бот рахує тригери й пише, коли кілька з них спрацювали в одному
  напрямку і модель це підтвердила.
- **Перевірка точності** — кожен прогноз через 5, 10 і 15 хв звіряється з реальною ціною з MT5;
  `/stats` показує точність, калібрування і порівняння з простою базовою лінією.

Бот **лише читає** дані з терміналу і нічого не торгує. Відсотки — оцінка моделі, а не гарантія.
Якщо `/stats` показує, що бот не кращий за базову лінію, — переглядайте промпт і тригери,
а не довіряйте відсоткам.

> **Чому MT5, а не API Bybit.** USOUSD.s — інструмент Bybit TradFi, він живе лише в MetaTrader 5.
> Bybit API v5 його не бачить. У CFD немає біржової стрічки угод, стакану, open interest,
> funding і long/short ratio, тому бот їх не використовує.

## Вимоги

- **Лише Windows.** Офіційний пакет `MetaTrader5` для Python працює тільки на Windows
  і спілкується із запущеним терміналом на тому самому комп'ютері.
- **Термінал MT5 запущений і залогінений** (рахунок Bybit TradFi, сервер `Bybit-Live-6`).
  Якщо термінал закрити, бот напише в Телеграм і перепідключиться, щойно термінал з'явиться.
- **Python 3.11+ 64-bit** (термінал MT5 64-бітний).
- Python і термінал мають працювати **від одного користувача Windows і з однаковими правами**:
  обидва звичайні або обидва «від імені адміністратора». Інакше пакет не бачить термінал
  (помилка `initialize: -10003 IPC initialize failed`).

### Пароль інвестора (рекомендовано)

Боту не потрібен торговий доступ. Безпечніше дати йому **пароль інвестора**: з ним можна лише
дивитися котирування й рахунок, а відкрити чи закрити угоду неможливо.

- Пароль інвестора задається в терміналі (*Сервіс → Налаштування → Сервер → Змінити*)
  або в кабінеті Bybit у розділі TradFi/MT5.
- Якщо вписати `MT5_LOGIN`/`MT5_PASSWORD`/`MT5_SERVER` у `.env`, бот при старті перелогінить
  термінал цим паролем, і термінал теж стане «лише для читання». Тому якщо ви торгуєте в цьому
  самому терміналі — поставте для бота **окрему копію MT5** (інша папка) і вкажіть шлях до неї
  в `MT5_PATH`.
- Якщо поля `MT5_*` залишити порожніми, бот просто підключиться до терміналу, у якому вже
  виконано вхід.

## Швидкий старт (PowerShell)

```powershell
cd C:\mybot
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
Copy-Item .env.example .env       # заповнити значення (див. нижче)
notepad .env
python scripts\mt5_snapshot.py    # перевірити, що бот бачить USOUSD.s
python -m bot.main --check-config
python -m bot.main
```

Після запуску напишіть боту `/start`.

> Щоб кирилиця не ламалася при збереженні виводу у файл, перед запуском виконайте
> `$env:PYTHONUTF8 = "1"` і `[Console]::OutputEncoding = [System.Text.Encoding]::UTF8`.

| `TELEGRAM_BOT_TOKEN` | токен від @BotFather |
| `TELEGRAM_OWNER_ID` | ваш числовий Telegram ID (дізнатися: @userinfobot). Решту користувачів бот мовчки ігнорує |

| `MT5_LOGIN` | номер рахунку MT5 (необов'язково) |

| `MT5_SERVER` | `Bybit-Live-6` (необов'язково) |

### `config.yaml` — усе інше

- `mt5` — символ (`USOUSD.s`), таймфрейми, кількість свічок, зсув часу сервера
  (`auto` визначає його за свіжим тіком; Bybit-Live-6 зараз UTC+3), паузи перепідключення.
- `market` — комісія за одну сторону (`commission_pct`, за замовчуванням 0) і години роботи ринку.
- `alerts` — чутливість, пороги тригерів, паузи, ліміт запитів до моделі.
- RSS-стрічки, ключові слова, календар подій, часовий пояс показу (`display.timezone`,
  наприклад `Europe/Kyiv`).

Невідомий ключ у файлі — помилка (захист від одруківок).

Промпт моделі лежить у `prompts/analysis.md`; його можна правити без перезапуску — бот читає файл
при кожному аналізі, а версія промпту зберігається з кожним прогнозом.

## Що бачить модель

Технічний аналіз 5 хв (RSI, EMA 9/21/50, ATR, VWAP, рівні підтримки й опору, поточна свічка),
хвилинні свічки, тренд 15 і 60 хв, Bid/Ask і спред, тікову активність (тіків за 1/5/15 хв проти
звичайного темпу), стан спреду, свіжі новини й календар подій. Пріоритет у промпті:
теханаліз 5 хв → тіковий обсяг → свіжі новини й події (EIA, ОПЕК+).

Обсяг у CFD — **тіковий** (кількість змін ціни за свічку), біржового обсягу немає.
Свічки MT5 будуються по **Bid**; лонг відкривається по Ask.

## Як працюють автосповіщення

Кожні 15 с рахуються три тригери, кожен з напрямком:

| Тригер | Умова (за замовчуванням) |
| --- | --- |
| Тіковий обсяг | тіків за 5 хв > 2,5× звичайного темпу за годину; напрямок — куди пішла ціна |
| Імпульс | рух за 1 хв > 1× ATR(14) на 5 хв |
| Пробій рівня | закриття 5-хв свічки за найближчим рівнем щонайменше на 2 спреди |

Коли в одному напрямку спрацювало N тригерів (чутливість: high 1, medium 2, low 3), запускається
аналіз моделлю. Сповіщення надсилається, лише якщо модель не каже «чекати» і дає цьому напрямку
≥ 60%. Відфільтровані сигнали теж зберігаються (`alert_filtered`) — у `/stats` видно, чи фільтр
корисний.

**Розширення спреду** (спред > 2× медіани за годину) — окреме попередження «угоди зараз дорожчі»,
одне на епізод. Це не сигнал і на напрямок не впливає; модель отримує прапорець `widened`.

Запобіжники: пауза 12 хв після сповіщення (протилежний напрямок — через 5 хв); тихий режим
±15 хв навколо подій з календаря з одним попередженням; не більше 6 автоматичних запитів
до моделі на годину.

**Dry-run**: `python -m bot.main --dry-run` або `alerts.dry_run: true` — сигнали лише пишуться в лог.

### Години роботи ринку

Ринок вважається **закритим**, якщо:

- за розкладом сесії (`market.session`) йдуть вихідні або щоденна перерва. За замовчуванням
  розклад, як у ф'ючерса WTI на CME, за часом Нью-Йорка: з неділі 18:00 до п'ятниці 17:00,
  щоденна перерва 17:00–18:00 (літній/зимовий час враховується сам);
- або нових тіків немає довше за `market.no_ticks_closed_sec` (120 с).

Тоді кнопка аналізу відповідає «🌙 ринок закритий» (модель не викликається), а автосповіщення
не надсилаються, зокрема попередження про події й спред. Якщо розклад у брокера інший — виправте
`market.session` у `config.yaml`.

### Зв'язок з MT5

Бот кожні 15 с перевіряє термінал. Якщо термінал закрито або він втратив зв'язок з брокером,
бот один раз пише в Телеграм «⚠️ Не вдається отримати дані MT5», перепідключається з паузами
до 5 хв і пише «✅ Дані MT5 знову доступні», коли зв'язок повернеться.

## Як рахується точність

- **Витрати на угоду** = поточний спред (з MT5 у момент аналізу) + `2 × market.commission_pct`.
  Вони записуються з кожним прогнозом.
- **Вдалий** прогноз: ціна пішла в передбаченому напрямку більше, ніж на витрати на угоду.
  **Невдалий** — так само проти. Решта — **нейтральний**.
- Тейк має бути далі від входу, ніж витрати на угоду, інакше модель переробляє відповідь.
- Для «чекати» окремо рахується, чи справді не було руху, більшого за витрати.
- Тейк і стоп перевіряються за 1-хв свічками MT5: лонг — по Bid, шорт — по Ask (Bid + спред свічки).
  Якщо обидва спрацювали в одній свічці — рахується стоп.
- Якщо горизонт припав на перерву в торгах, ціною горизонту вважається останнє закриття перед
  перервою (результат з'явиться після відкриття).
- **Основний горизонт — 5 хв** (`tracking.main_horizon_min`): бот прогнозує 5-хвилинну свічку,
  тому всі ключові метрики `/stats` рахуються на ньому. 10 і 15 хв показуються нижче, у блоці «Додатково».
- **Калібрування**: для кошиків 50–55, 55–60, 60–65, 65–70, 70+ % — як часто ціна справді пішла в бік
  більшого відсотка. Враховуються всі прогнози з напрямком > 50%, зокрема «чекати» і відфільтровані.
- **Базова лінія**: «йти за напрямком останньої закритої 5-хв свічки» — на тих самих прогнозах
  з напрямком > 50% (не лише на явних сигналах). Якщо довірчі інтервали перетинаються, звіт пише
  «різниця в межах похибки».
- **Довірчі інтервали**: біля кожного відсотка — 95% інтервал Вілсона і кількість прогнозів;
  ⚠️ — менше 30 прогнозів.
- **Гіпотетичний P&L**: на кожен прогноз з напрямком > 50% (і окремо лише на явні лонг/шорт)
  відкривається угода на 5 хв; результат = рух у бік прогнозу мінус витрати, записані з прогнозом.
  Сума проста, без реінвестування; максимальна просадка — найбільше падіння кривої суми від її піку.
  Угоди можуть перекриватися в часі, тож це оцінка якості прогнозів, а не реальний торговий рахунок.

База — `data/bot_mt5.db`, окремо від бази Bybit-версії (`data/bot.db`), щоб прогнози
двох різних інструментів не змішувалися.

## Деплой: свій ПК або Windows-VPS

Бот має працювати там, де відкритий термінал MT5: на вашому ПК (який не засинає) або на
Windows-VPS (Windows Server 2019+ чи Windows 10/11, від 2 ГБ RAM). Linux-VPS не підходить.

1. **Термінал MT5 стартує сам.** Увійдіть у рахунок з «Зберегти пароль». Покладіть ярлик
   `terminal64.exe` в автозавантаження (`Win+R` → `shell:startup`).
2. **Бот стартує сам.** Один раз виконайте:

   ```powershell
   powershell -NoProfile -ExecutionPolicy Bypass -File deploy\windows\install-task.ps1
   ```

   Задача «USOUSD bot» запускає `deploy\windows\run-bot.ps1` через хвилину після входу
   у Windows (у вашій сесії, поруч із терміналом) і перезапускає бота після збою.
   Якщо Windows відповість «Відмовлено в доступі», запустіть цю команду в PowerShell від імені
   адміністратора — сам бот однаково працюватиме зі звичайними правами.
3. **Комп'ютер не засинає:** *Параметри → Система → Живлення* — «Ніколи» для сну.
4. **Windows-VPS:** термінал MT5 працює лише в сесії користувача, тому після перезавантаження
   сервера потрібен автоматичний вхід (наприклад, Sysinternals Autologon). Від'єднуйтеся від RDP
   через закриття вікна, а не «Вийти», — інакше сесія завершиться разом з терміналом.

| Дія | Команда (PowerShell, у `C:\mybot`) |
| --- | --- |
| Запустити зараз | `Start-ScheduledTask -TaskName "USOUSD bot"` |
| Запустити у вікні (видно лог) | `powershell -NoProfile -ExecutionPolicy Bypass -File deploy\windows\run-bot.ps1` |
| Зупинити | `powershell -NoProfile -ExecutionPolicy Bypass -File deploy\windows\stop-bot.ps1` |
| Лог | `Get-Content logs\bot.log -Wait -Tail 50` |
| Оновити код | зупинити → `git pull` → `.\.venv\Scripts\python.exe -m pip install -r requirements.txt` → запустити |
| Резервна копія бази | `.\.venv\Scripts\python.exe scripts\backup_db.py` (у `backups\`, зберігаються 14 днів) |

Щоденна резервна копія через Планувальник:

```powershell
schtasks /Create /SC DAILY /ST 03:17 /TN "USOUSD bot backup" /TR "C:\mybot\.venv\Scripts\python.exe C:\mybot\scripts\backup_db.py"
```

При кожному старті бот пише власнику «✅ Бот запущено», тож перезапуски видно в чаті.
