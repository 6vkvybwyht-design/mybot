# USOUSDT Bybit — Telegram-бот аналітики

Особистий Telegram-бот, який аналізує безстроковий контракт **USOUSDT** на Bybit
(таймфрейм 5 хв). Він збирає свічки, угоди китів, стакан, open interest, funding і свіжі
новини, передає це моделі Claude і надсилає розбір з ймовірністю лонгу та шорту.

- **За кнопкою** «📊 Аналіз зараз» — розбір приблизно за 20–40 секунд.
- **Автосповіщення** — бот цілодобово рахує тригери і пише, коли кілька з них
  спрацювали в одному напрямку і модель це підтвердила.
- **Перевірка точності** — кожен прогноз через 5, 10 і 15 хв звіряється з реальною ціною;
  `/stats` показує точність, калібрування і порівняння з простою базовою лінією.

Бот **лише читає** публічні дані Bybit (ключі Bybit не потрібні) і нічого не торгує.
Відсотки — оцінка моделі, а не гарантія. Якщо `/stats` показує, що бот не кращий
за базову лінію, — переглядайте промпт і тригери, а не довіряйте відсоткам.

## Швидкий старт (локально)

Потрібен Python 3.11+.

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env      # заповнити значення (див. нижче)
python -m bot.main --check-config
python -m bot.main
```

Після запуску напишіть боту `/start`.

### `.env` — секрети

| Змінна | Що це |
| --- | --- |
| `TELEGRAM_BOT_TOKEN` | токен від @BotFather |
| `TELEGRAM_OWNER_ID` | ваш числовий Telegram ID (дізнатися: @userinfobot). Решту користувачів бот мовчки ігнорує |
| `ANTHROPIC_API_KEY` | ключ Anthropic API |
| `ANTHROPIC_MODEL` | модель: `claude-opus-5-5` (найточніша) або `claude-sonnet-5-5` (удвічі дешевша і швидша) |

### `config.yaml` — усе інше

Символ, комісія taker, пороги китів і тригерів, чутливість, паузи, ліміт запитів до моделі,
RSS-стрічки, ключові слова, календар подій, часовий пояс показу (`display.timezone`,
наприклад `Europe/Kyiv`). Невідомий ключ у файлі — помилка (захист від одруківок).
Інший файл конфігу можна підставити змінною `BOT_CONFIG=/шлях/до/config.yaml`.

Промпт моделі лежить у `prompts/analysis.md`; його можна правити без перезапуску —
бот читає файл при кожному аналізі, а версія промпту зберігається з кожним прогнозом.

## Команди

| Команда | Дія |
| --- | --- |
| `/start` | привітання і клавіатура |
| `/analyze` або «📊 Аналіз зараз» | аналіз зараз |
| `/status` або «ℹ️ Статус» | ціна, стан WebSocket, сповіщення, найближча подія |
| `/stats` або «📈 Статистика» | точність за 7 / 30 днів і весь час |
| `/alerts on` · `/alerts off` або кнопка 🔔/🔕 | автосповіщення |
| `/sensitivity low\|medium\|high` | скільки тригерів потрібно: 4 / 3 / 2 |
| `/event YYYY-MM-DD HH:MM назва` | додати подію в календар (час UTC) |
| `/events` | події на тиждень |
| `/export` | усі прогнози в CSV |

Налаштування з Телеграму (сповіщення, чутливість, події) зберігаються в базі і переживають перезапуск.

## Як працюють автосповіщення

Кожні 15 с рахуються шість тригерів, кожен з напрямком:

| Тригер | Умова (за замовчуванням) |
| --- | --- |
| Кити | дельта китових угод за 5 хв > 3× середнього за 24 год |
| Обсяг | обсяг поточної 5-хв свічки > 2,5× середнього за 20 свічок |
| Open interest | зміна OI за 15 хв > 1%; напрямок — за рухом ціни |
| Стакан | bid/ask у межах ±0,3% > 70/30 і тримається ≥ 30 с |
| Пробій рівня | закриття 5-хв свічки за найближчим рівнем |
| Імпульс | рух за 1 хв > 1× ATR(14) на 5 хв |

Коли в одному напрямку спрацювало N тригерів (чутливість), запускається аналіз моделлю.
Сповіщення надсилається, лише якщо модель не каже «чекати» і дає цьому напрямку ≥ 60%.
Відфільтровані сигнали теж зберігаються (`alert_filtered`) — у `/stats` видно, чи фільтр корисний.

Запобіжники: пауза 12 хв після сповіщення (протилежний напрямок — через 5 хв); тихий режим
±15 хв навколо подій з календаря з одним попередженням; не більше 6 автоматичних запитів
до моделі на годину; якщо WebSocket мовчить > 30 с — тригери не рахуються, > 2 хв — бот пише
про проблему з'єднання.

**Dry-run**: `python -m bot.main --dry-run` або `alerts.dry_run: true` — сигнали лише пишуться в лог.

## Як рахується точність

- **Вдалий** прогноз: ціна пішла в передбаченому напрямку більше ніж на подвійну комісію
  (вхід + вихід, `2 × taker_fee_pct`). **Невдалий** — так само проти. Решта — **нейтральний**.
- Для «чекати» окремо рахується, чи справді не було руху більшого за подвійну комісію.
- Тейк і стоп перевіряються за 1-хв свічками; якщо обидва в одній свічці — рахується стоп.
- **Калібрування**: для кошиків 50–60%, 60–70%, 70%+ — як часто ціна справді пішла в бік більшого відсотка.
- **Базова лінія**: «йти за напрямком останньої закритої 5-хв свічки» на тих самих прогнозах.

## Перевірка з консолі

```bash
python -m bot.snapshot                  # надрукувати реальний знімок ринку (слухає WS 15 с)
python -m bot.analysis                  # знімок + аналіз моделлю, вивести JSON
python -m bot.analysis --snapshot s.json   # аналіз збереженого знімка
```

## Тести

```bash
pip install -r requirements-dev.txt
pytest
```

Тести не ходять у мережу: Bybit, Telegram і модель підмінені фейками (формат відповідей —
як у справжніх API), WebSocket перевіряється на локальному сервері.

## Деплой на VPS (Ubuntu 24.04, 1 vCPU / 1 ГБ RAM)

Бот працює як systemd-сервіс з автоперезапуском і піднімається сам після перезавантаження сервера.

> Bybit блокує доступ з деяких країн (зокрема США). Обирайте VPS у регіоні, з якого
> `curl https://api.bybit.com/v5/market/time` повертає JSON, а не помилку CloudFront.

```bash
# на сервері, від root
git clone <URL цього репозиторію> /tmp/usousdt-bot
sudo bash /tmp/usousdt-bot/deploy/install.sh <URL цього репозиторію> main
sudo nano /opt/usousdt-bot/.env          # заповнити секрети
sudo systemctl start usousdt-bot
```

Останній аргумент — гілка (поки зміни не злиті в `main`, вкажіть `claude/new-session-gb1tfz`).
Якщо репозиторій приватний, використайте URL з доступом, наприклад через
[deploy key](https://docs.github.com/en/authentication/connecting-to-github-with-ssh/managing-deploy-keys)
(`git@github.com:...`) або токен.

Скрипт встановлює пакети, ставить час сервера в UTC, створює системного користувача `usousdt`,
кладе код у `/opt/usousdt-bot`, створює virtualenv, реєструє сервіс `usousdt-bot` і щоденну
резервну копію бази о 03:17 UTC (`/opt/usousdt-bot/backups`, зберігаються 14 днів).

| Дія | Команда |
| --- | --- |
| Стан | `sudo systemctl status usousdt-bot` |
| Логи наживо | `sudo journalctl -u usousdt-bot -f` або `tail -f /opt/usousdt-bot/logs/bot.log` |
| Перезапуск | `sudo systemctl restart usousdt-bot` |
| Оновлення (`git pull` + перезапуск) | `sudo /opt/usousdt-bot/deploy/update.sh` |
| Ручна резервна копія | `sudo -u usousdt /opt/usousdt-bot/deploy/backup.sh` |

При кожному старті бот пише власнику «✅ Бот запущено», тож перезапуски видно в чаті.
Якщо в `.env` помилка або токен невірний, сервіс зупиняється з кодом 2 і не перезапускається
в циклі — дивіться `journalctl -u usousdt-bot`.

## Структура

```text
bot/
├── main.py            # запуск: Telegram + фонові задачі
├── config.py          # .env + config.yaml (з перевіркою)
├── app.py             # знімок → модель → база; спільне для кнопки і сповіщень
├── snapshot.py        # збирає все в один знімок
├── analysis.py        # запит до моделі, JSON-схема, валідація
├── triggers.py        # тригери автосповіщень
├── alerts.py          # фоновий цикл: паузи, тихий режим, ліміти
├── telegram/          # хендлери, клавіатура, owner-middleware, форматування
├── market/            # Bybit REST/WS, угоди, стакан, кити, індикатори
├── news/              # RSS, календар подій
└── tracking/          # SQLite, перевірка через 5/10/15 хв, статистика
prompts/analysis.md    # промпт для моделі
deploy/                # systemd, встановлення, оновлення, бекап
tests/
```
